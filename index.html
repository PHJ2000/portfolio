PR #6PR #20
문제

B재시도로 생기는 중복 저장 방지

PR #180
문제
같은 상품을 다시 고민하는 건 정상 요청이지만, 더블탭이나 timeout 재시도로 같은 요청이 두 번 저장되면 안 됩니다. 내용 기반 중복 제거로는 둘을 구분할 수 없었습니다.
해결
Idempotency-Key 계약과 사용자별 partial unique index로 "같은 요청의 재전송"만 걸러내고, 같은 내용의 새 요청은 허용
create unique index uk_saved_items_user_idempotency_key
    on saved_items(user_id, idempotency_key)
 where idempotency_key is not null;
같은 key → 기존 결과 반환key 없음 → 새 항목URL 상품 → 기존 중복 규칙 유지
